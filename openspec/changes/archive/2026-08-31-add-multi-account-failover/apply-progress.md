Observed results for both OpenAI completions and Anthropic messages:

| Scenario                             | Observed before native SDK conversion                                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| Non-OK HTTP response                 | Custom fetch saw `status: 429`, normalized headers, and bounded cloned `code`/`type` fields; native stream emitted `error`.           |
| Thrown fetch/network failure         | Custom fetch caught the original `TypeError` class/name and rethrew it; native stream emitted `error`.                                |

The abort probe produced `error` events in both cases and proved provenance by signal identity/state rather than elapsed time or message parsing. The non-OK probe proved that body fields can be extracted from a clone before SDK status-error conversion. The response-body probe proved that a forwarding body wrapper can retain the original read failure class.
